# 6.2. Git Hooks

Git hooks are scripts that are automatically executed by Git before or after specific events occur within a repository. They provide a powerful way to automate tasks and enforce standards, making them invaluable for development workflows.

---

## What Are Git Hooks?

Git hooks are custom scripts that run in response to various Git events, such as commits, merges, or pushes. These scripts can be used to:

- Enforce coding standards.
- Run tests or linting tools.
- Automate deployment tasks.
- Notify team members of changes.

Git hooks are stored in the `.git/hooks` directory of your repository. Each hook corresponds to a specific Git event and has a default script file (e.g., `pre-commit.sample`).

Hook scripts can be written in any programming or scripting language, such as Bash, Python, Ruby, or Perl, as long as the interpreter for the language is available on the system.

---

## Types of Git Hooks

Git hooks are categorized into two types:

### Client-Side Hooks

Client-side hooks are triggered by actions performed on the local repository, such as committing changes or merging branches. Examples include:

- **`pre-commit`:** Runs before a commit is created. Often used for code formatting or linting.
- **`prepare-commit-msg`:** Modifies the default commit message before it’s presented to the user.
- **`commit-msg`:** Validates the commit message.
- **`post-commit`:** Executes after a commit is made. Useful for notifications.

### Server-Side Hooks

Server-side hooks are triggered by actions on a remote repository, such as receiving a push. Examples include:

- **`pre-receive`:** Runs before the remote repository accepts a push. Used for validation or access control.
- **`update`:** Checks the branch being updated.
- **`post-receive`:** Executes after a push is received. Commonly used for deployment.

---

## Setting Up Git Hooks

To set up a Git hook:

1. Navigate to the `.git/hooks` directory in your repository.
2. Locate the hook file you want to enable (e.g., `pre-commit.sample`).
3. Rename the file by removing the `.sample` extension (e.g., `pre-commit`).
4. Make the file executable:
   ```bash
   chmod +x .git/hooks/pre-commit
   ```
5. Add your script to the file.

### Example: Pre-Commit Hook

The following `pre-commit` script prevents commits if any file contains trailing whitespace:

```bash
#!/bin/bash

git diff --cached --check
if [ $? -ne 0 ]; then
  echo "Commit aborted due to trailing whitespace."
  exit 1
fi
```

## Sharing Hooks Across Teams

Since Git hooks are stored in the `.git/hooks` directory, they are not shared by default. To share hooks with your team, consider the following approaches:

- **Store hooks in your repository:** Create a `hooks` directory in your project and include the scripts. Add setup instructions or automate the setup with a script.
- **Use a Git configuration setting:** Configure a shared hooks directory:
  ```bash
  git config core.hooksPath /path/to/shared/hooks
  ```

---

## Best Practices for Git Hooks

- **Keep scripts lightweight:** Avoid adding long-running tasks that can slow down the workflow.
- **Test hooks thoroughly:** Ensure hooks work on all team members' environments.
- **Use meaningful error messages:** Help users understand why a hook failed and how to fix it.
- **Version control shared hooks:** If you share hooks, store them in the repository to ensure consistency.
