# 3.1. Working with Branches

## Understanding Branching in Git

Branching is one of Git’s most powerful features, allowing developers to work on different tasks, such as new features or bug fixes, without affecting the main codebase.

A branch in Git is a lightweight pointer to a specific commit. Branching allows developers to work on isolated changes without affecting the main project. The default branch in most repositories is typically `main` or `master`, but you can create as many branches as needed for development, experimentation, or bug fixes.
    
Key benefits of branching:
- **Parallel Development**: Teams can work on multiple features simultaneously.
- **Safe Experimentation**: Changes can be tested and refined without impacting the stable codebase.
- **Simplified Collaboration**: Separate branches for each task ensure clean integration of changes.

## Creating, Listing, and Switching Branches

### Creating a Branch
To create a new branch:
```bash
git branch <branch-name>
```
The new branch will initially point to the same commit as the branch you are currently on.

### Listing Branches
To view all branches in the repository:
```bash
git branch
```
The current branch is indicated with an asterisk (*).

### Switching Branches
To move to another branch:
```bash
git switch <branch-name>
```
Alternatively:
```bash
git checkout <branch-name>
```
(*`git switch` is preferred in modern Git versions.*)

### Creating and Switching Simultaneously
To create and switch to a new branch in one command:
```bash
git switch -c <branch-name>
```
Or:
```bash
git checkout -b <branch-name>
```

## Basic Branching Workflow
A typical workflow might look like this:
1. Start on the main branch:
   ```bash
   git switch main
   ```
2. Create and switch to a feature branch:
   ```bash
   git switch -c feature/new-feature
   ```
3. Make changes, stage, and commit them:
   ```bash
   git add .
   git commit -m "Add new feature"
   ```
4. Push the feature branch to a remote repository:
   ```bash
   git push origin feature/new-feature
   ```

By following this workflow, your main branch remains stable while development progresses on isolated branches.
