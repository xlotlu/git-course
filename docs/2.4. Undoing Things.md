# 2.4. Undoing Things

In Git, it’s common to make mistakes or want to change something after committing, staging, or modifying files. Thankfully, Git offers powerful tools to undo changes safely. This chapter covers how to amend commits, unstage files, discard unwanted changes, and handle file removals and renames.

---

## Amending Commits

Sometimes, after making a commit, you might realize you forgot to include a file, mistyped the commit message, or need to adjust something minor. The `git commit --amend` command lets you modify the most recent commit.

### Changing the Last Commit Message
Use this command to edit the message of your last commit:
```bash
git commit --amend
```
This opens your default text editor, allowing you to modify the message.

### Adding Files to the Last Commit
If you forgot to include a file in your last commit:
1. Stage the missing file(s):
   ```bash
   git add <file>
   ```
2. Amend the commit:
   ```bash
   git commit --amend
   ```
The amended commit will replace the previous one.

> **Note:** Amending commits rewrites history. Avoid using it if you’ve already pushed the commit to a shared repository.

---

## Unstaging Files and Discarding Changes

### Unstaging Files
To unstage a file that you’ve added to the staging area, use the `git restore --staged` command:
```bash
git restore --staged <file>
```
This removes the file from the staging area without affecting its changes in the working directory.

Alternatively, you can use:
```bash
git reset HEAD <file>
```
Both commands achieve the same result.

### Discarding Changes in the Working Directory
If you’ve made changes to a file and want to discard them completely, returning it to its last committed state, use:
```bash
git restore <file>
```
Be cautious, as this action is irreversible.

For older Git versions (before 2.23), use:
```bash
git checkout -- <file>
```

### Discarding All Changes
To discard all changes in the working directory:
```bash
git restore .
```
This resets all modified files to their last committed state.
