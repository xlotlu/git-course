# 5.1. Rebasing

Rebasing in Git is a powerful way to modify your project’s commit history. It allows you to streamline and reorganize commits, making the history cleaner and more understandable. However, rebasing requires caution, especially in collaborative environments.

---

## What is Rebasing?

Rebasing is the process of moving a branch to a new base commit. Instead of merging changes into your branch, rebasing integrates your changes onto a different branch’s history. This creates a linear commit history without merge commits.

### How Rebasing Works

Consider a branch structure where `feature` branches off `main`:

```
main:    A---B---C
              \
feature:       D---E
```

Rebasing `feature` onto `main` applies the commits `D` and `E` on top of `C`:

```
main:    A---B---C
                    \
feature (rebased):   D'---E'
```

Here, `D'` and `E'` are new commits representing the same changes as `D` and `E`, but with a different base.

To rebase a branch:

```bash
git checkout feature
git rebase main
```

---

## Interactive Rebasing

Interactive rebasing provides control over each commit in the rebase process. It allows you to edit, squash, reorder, or remove commits.

### Starting an Interactive Rebase

```bash
git rebase -i <base-branch>
```

For example:

```bash
git rebase -i main
```

This opens an editor with a list of commits:

```
pick abc123 Commit message 1
pick def456 Commit message 2
pick ghi789 Commit message 3
```

### Actions During Interactive Rebase

- **pick**: Keep the commit as-is.
- **reword**: Edit the commit message.
- **edit**: Amend the commit’s changes or message.
- **squash**: Combine this commit with the previous one.
- **drop**: Remove the commit.

For example, to squash the second commit into the first, change the lines to:

```
pick abc123 Commit message 1
squash def456 Commit message 2
pick ghi789 Commit message 3
```

After saving, Git will prompt you to edit the combined commit message.

#### Example 1: Reordering Commits
If you want to swap the order of commits, modify the list. For example:

```
pick abc123 Commit message 1
pick def456 Commit message 2
pick ghi789 Commit message 3
```

Change it to:

```
pick def456 Commit message 2
pick abc123 Commit message 1
pick ghi789 Commit message 3
```

Save the file, and Git will reapply the commits in the specified order.

#### Example 2: Splitting a Commit
To split a commit, mark it as `edit`:

```
pick abc123 Commit message 1
edit def456 Commit message 2
pick ghi789 Commit message 3
```

When Git pauses, unstage the changes:

```bash
git reset HEAD^
```

Then, add and commit the changes in smaller chunks:

```bash
git add <file>
git commit -m "Partial commit message"
```

Finally, continue the rebase:

```bash
git rebase --continue
```

#### Example 3: Dropping a Commit
To remove a commit, change `pick` to `drop`:

```
pick abc123 Commit message 1
drop def456 Commit message 2
pick ghi789 Commit message 3
```

Git will skip the dropped commit during the rebase process.

---

## When to Rebase and When Not To

### When to Use Rebasing

1. **Private Branches**: Rebase frequently to keep your branch updated with the main branch without introducing merge commits.
2. **Cleaning Up Commit History**: Use interactive rebasing to organize commits before merging them into shared branches.
3. **Linear History**: Rebasing helps maintain a clean, linear project history, which is easier to navigate.

### When to Avoid Rebasing

1. **Shared Branches**: Rebasing rewrites commit history, which can cause issues if others are working on the same branch.
2. **Published Commits**: Avoid rebasing commits that have already been pushed to a remote repository, as it may lead to conflicts.

### Alternatives to Rebasing

- **Merging**: Use `git merge` if you prefer to preserve the full history, including merge commits.
- **Cherry-Picking**: If you need specific commits from one branch, use `git cherry-pick` instead of rebasing the entire branch.
